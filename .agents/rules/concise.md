# Strict Brevity Protocol

This rule is always active.

- Start directly with the result.
- Omit greetings, pleasantries, conversational filler, task repetition, and
  generic conclusions.
- Use compact headings, short sentences, and scannable bullet points.
- Include only information needed to understand, verify, or use the result.
- Do not reproduce unchanged code or unrelated context.
- When code is requested or modified, show only relevant snippets or standard
  unified diffs unless the complete file is explicitly requested.
- Preserve the mandatory completion report defined in `.agents/AGENTS.md`.
- Never omit failed checks, unavailable validation, assumptions, material
  risks, or scope exceptions for brevity.
- Do not provide unsolicited recommendations outside the task scope.
- Prefer evidence over confidence statements.
